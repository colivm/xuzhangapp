你在 xuzhangapp 实现 Task MEMORY-LOOP — 记望回指 · 产品记忆机制全链路（Web 先行 · iOS 同规则移植）。

================================================================================
零、战略锚点（@PRODUCT_NORTH_STAR.md §0.6 · 改代码前先读）
================================================================================

护城河一句话：
  **记下的生活痕迹，在回望时被认回来。**

三层品类（做取舍时用）：
  · 普通记账 → 记多少钱          → 叙账不拼
  · 温柔记账 → 温柔总结          → 可模仿，非护城河
  · **叙账**   → **记得当时留下过什么** → **本任务目标区间**

每笔账两层（全链路共用）：
```text
结构层（骨架）：金额、分类、时间、品牌 — 可靠、可查、可编辑；默认藏在附录/细查
生活痕迹层：   备注 title、mood、场景句、emotionTag — 回望时「认回来」的素材
```

闭环：
```text
记 → 鼓励留下可被引用的短句（非必填）
存 → 脏标题/习惯预填不污染生活痕迹层
望 → 锚点 ECHO：每 week/month 最多回指 1 次真实字段；无素材则静默
```

双评审问句（每个落点自检）：
  1. @PRODUCT_NORTH_STAR.md §0.3 — 更温柔地看见生活，还是拉回管钱工具？
  2. §0.6 — **用户能认出是哪一次自己记下的吗？** 认不出 = 编散文，不是记忆机制。

平衡（勿偏）：
  · 温柔 ≠ 删能力 — 结构层在细查/编辑必须可达
  · 回指 ≠ 满屏引用 — 多数周无手写备注时，行为与现有一致，正常
  · 本地规则 only — 不用 AI 编造「回忆」

建议顺序：**Web 验证闭环手感 → iOS EchoAnchorService 同规则移植**

================================================================================
二、记 · 留下可被认回的素材
================================================================================

目标：用户 **可选** 留下 4～18 字生活句；不增加表单负担。

--------------------------------------------------------------------------------
2.1 记账 life-slip（Web app.js · iOS RecordView 仅文案壳）
--------------------------------------------------------------------------------

当 preview 主行 title 来自 **场景包/习惯预填**（非用户手打）时：
  · hint 轻字（已有则改文案）：「想被将来认出来，可改几个字」
  · **禁止** modal、红点、计数器、成就 — 一句 muted hint 即可

当用户 **在备注框手打或改过** preview 主行（trim 后 ≥4 字且非默认/脏串）：
  · hint 可换：「会像这样留在账本里」
  · 保存时（Web item 对象 / iOS HomeItem）设 `userEditedTitle = true`（若无字段则 Web 用 `titleSource: "user"`）

**不做**：强制填备注、保存前拦截、「写一句才能存」

--------------------------------------------------------------------------------
2.2 场景包 vs 用户声纹（存盘语义 · 可选 MVP）
--------------------------------------------------------------------------------

保存 title 时区分来源（便于 §三 选材，避免全靠 heuristic）：

| 来源 | 标记 | 能否进锚点池 |
|------|------|--------------|
| 用户手打/改过 | userEditedTitle 或 titleSource=user | ✅ 优先 |
| 场景包一键 | titleSource=scenePack | ⚠️ 仅当 4～18 字且非模板腔 |
| 习惯预填 | titleSource=habit / isHabitTitle | ❌ MVP 不进锚点池 |
| 品牌 displayName | titleSource=brand | ❌ 无用户改写不进 |
| 分类默认 | defaultRecordTitle | ❌ |

Web：localStorage item 增字段即可；iOS：HomeItem Codable 增可选字段，旧数据 default false/nil。

================================================================================
三、存 · 生活痕迹层不被污染
================================================================================

目标：**同一套 eligibility** 服务 ECHO 选材 + 习惯池过滤 + 将来审计。

在 Web 抽函数（iOS 进 EchoAnchorService）：

```text
isEligibleLifeTraceTitle(title, item, category) → boolean
isDirtyTraceTitle(title) → boolean   // OCR 时间/状态栏 · 对齐 A5
isBrandHardTitle(title, merchantBrandId) → boolean
```

硬条件（title 锚点候选须 **全部** 满足）：
  · 去空白后 **4～18 字**（character）
  · ≠ category.defaultRecordTitle（「吃饭的一小笔」等）
  · ≠ isDirtyTraceTitle（08:38、M月d日、OCR 脏串 — 对齐 PROMPT_修复-A2至A5 §A5）
  · ≠ isBrandHardTitle（title 等于品牌 displayName/别名且无 userEditedTitle）
  · ≠ 习惯预填短句（isHabitTitle — MVP 一律 exclude，除非 userEditedTitle）
  · 不含隐私 denylist：密码、身份证、银行卡、验证码

**与 A4 协同**：用户删空备注后不抢写 habit — 已实现则回归；未实现则本任务 **不扩 scope**，只注释依赖 A4。

RecordPrefillService（iOS）：isHabitTitle / 脏标题 regex 与 Web isDirtyTraceTitle **同规则**（可抄 Web 实现到 Swift）。

================================================================================
四、望 · 弱闭环（不占锚点 cap）
================================================================================

痕迹票根 slip（Web trace-slip · iOS StatsWebView 票根）：
  · 若 emotionTag 存在且 ≠ inferEmotionTag(category, amount) 默认
  · meta 行或 title 下加 **muted** mood 字（class trace-slip-mood / life-slip-mood）
  · **不算**「锚点句」，不占用每 period 1 次

目的：记→望 日常可见，不等切片。

================================================================================
五、望 · 锚点 ECHO（每 period 最多 1 句 · 核心）
================================================================================

函数（Web app.js · iOS EchoAnchorService.swift 同名语义）：

```text
pickEchoAnchor(items, periodKey) → null | { snippet, kind, itemId }
formatEchoAnchorSentence(anchor) → String
```

periodKey：week = ISO 周标识；month = yyyy-MM

--------------------------------------------------------------------------------
5.1 选材
--------------------------------------------------------------------------------

软排序（合格 title 池取最高；同分 stableHash(item.id + periodKey) % 5）：
  +30  period 内最近 7 天
  +25  emotionTag 非默认
  +15  金额不极端（P25～P75 或 ≤ 中位数×2）
  +10  title 6～14 字
  +5   有 brand 但 userEditedTitle
  +5   userEditedTitle === true（若有字段）

降级（**仅 title 池 0 条** 且 items.length ≥ 2）：
  · 选 1 条非默认 emotionTag，kind=emotion，snippet=tag 原文
  · MVP 默认 **开启**；仍无 → null

频率：
  · 同一 periodKey **全局 1 条** Anchor（切片 / 周记 / 月记共用）
  · items.length < 2 → null（防硬煽）

--------------------------------------------------------------------------------
5.2 锚点句模板（≤3 · hash 轮换 · 禁止 coach/占比/预算）
--------------------------------------------------------------------------------

kind=title（二选一）：
  A. 「有一笔你写下「{snippet}」，像是那天给自己留的一点照顾。」
  B. 「{snippet}」—— 有一笔是这样留在账本里的。」

kind=emotion（一条）：
  C. 「有一次你标记过「{snippet}」，像一段很小的生活注脚。」

snippet：title 原文（已 4～18 字不截）；emotion 用 tag 原文

--------------------------------------------------------------------------------
5.3 落点（同 period UI 只出现 1 次）
--------------------------------------------------------------------------------

优先级（写进代码注释）：

  **1. 周/月切片 highlight 幕**（主）
      Web buildTraceSliceChapters type=highlight
      iOS PlaybackService highlight 章
      有 anchor → narration = formatEchoAnchorSentence
      无 anchor → 保持现有结构叙述

  **2. 复盘周记/月记**（备）
      formatWeeklyJournalText / formatMonthlyJournalText **末尾** 追加
      **仅当本 period 切片未展示锚点时**

同屏禁止重复；禁止 snippet 空仍输出。

--------------------------------------------------------------------------------
5.4 与「空泛 / 工具」对照
--------------------------------------------------------------------------------

  ✅ 「有一笔你写下「加班后吃点热乎的」，像是那天给自己留的一点照顾。」
  ✅ slip 上 muted「片刻停靠」（非默认 emotionTag）
  ❌ 「这周的你，在温柔与忙碌之间寻找平衡。」（空泛 · 非用户字段）
  ❌ 「餐饮占比 42%，建议关注。」（工具）
  ❌ 无素材仍生成「温柔回忆段」（假记忆）

若 Playback 现有 fallback 含 **无字段支撑** 的「感受总结」，本任务 **不删池子**，但 highlight 幕有 anchor 时 **必须** 用 anchor 替换该幕 narration。

七、验收（Web 造数 → iOS 同规则）
================================================================================

造数：
  1. 3 笔含手写「加班后吃点热乎的」→ 切片 **或** 周记 **1 次** 锚点
  2. 全默认标题/脏串/习惯预填 → 无锚点，叙述零回归
  3. 无合格 title 有非默认 emotionTag → 可选 C 模板
  4. 同周切片已展示 → 周记不重复
  5. slip 可见非默认 emotionTag（§四）
  6. 场景包预填 title → 不进锚点池；用户改 4 字后 → 可进池
  7. life-slip hint 出现/切换正确，无强制填备注

  [ ] §0.3 — 首屏仍读生活，非 KPI 报表
  [ ] §0.6 — 锚点句可指认到具体一笔
  [ ] 无锚点周期与改前一致
  [ ] Web / iOS eligibility + 选材同结果（同造数）
