> 若需 **记+存+望** 一并做，优先用 `PROMPT_功能-记望回指_全链路.txt`；本文 = 其中 **§五 望** 的独立可执行版。
================================================================================
一、产品目标（为何做 · 综合共识）
================================================================================

每笔账两层：
  · **结构信息（骨架）**：金额、分类、时间、品牌 — 回望已在读
  · **生活痕迹（入口）**：备注 title、mood、场景句、emotionTag — 下一步要「有概率」回指

质变：
  从「温柔地总结账单」→「它记得我当时为什么记下这一笔」。

做法（MVP 边界）：
  · **本地规则 only**，不做 AI
  · 每 week/month **最多 1 条**锚点句，**同一段正文只出现 1 次**
  · 凑不齐合格素材 → **静默**，结构叙述不变（不编散文填空）

示例：
  记：「加班后吃点热乎的」
  望：「有一笔你写下「加班后吃点热乎的」，像是那天给自己留的一点照顾。」
  而非仅：「餐饮出现得多一点。」

平衡（勿忘）：
  第一眼仍是生活；锚点是「认得出自己」的底气，不是满屏引用。
  评审问句：**用户能认出是哪一次自己记下的吗？**

不肉麻：
  · 不每次都引用
  · 只引短句 + 一句轻收束，不 coach、不心理分析
  · 模板 ≤3 条，stable hash 轮换

================================================================================
三、选材 pickEchoAnchor(items, periodKey) → null | Anchor
================================================================================

Anchor = { snippet: String, kind: "title"|"emotion", itemId }

periodKey：week = 当前 ISO 周标识；month = yyyy-MM

--------------------------------------------------------------------------------
3.1 硬过滤（title 锚点候选 · 用户 MVP 核心）
--------------------------------------------------------------------------------

title 去空白后须 **全部** 满足：
  · 长度 **4～18 字**（按 character）
  · **≠** 分类默认标题（「吃饭的一小笔」「今天的一小笔」；iOS：Category.defaultRecordTitle）
  · **≠** 纯时间/日期/OCR 脏串（对齐 A5 / RecordPrefillService 脏标题 regex）
  · **≠** 品牌硬标题（MerchantBrandCatalog 命中且 title 等于 displayName/别名/解析 fallback，无用户改写）
  · **≠** 轻量隐私串（含：密码、身份证、银行卡、验证码 → skip 该条）

以下 **不** 进入 title 锚点池：
  · isHabitTitle==true 的短习惯句（2～12 字预填池）— 除非未来有「用户改过」标记；MVP 无标记则一律 exclude

--------------------------------------------------------------------------------
3.2 软排序（合格池中选 1 条 · 综合优先级）
--------------------------------------------------------------------------------

对每条合格 title 计分，取最高：

  +30  落在 period 的 **最近 7 天** 内
  +25  emotionTag 存在且 **≠** inferEmotionTag(category, amount) 默认
  +15  金额 **不极端**（period 内介于 P25～P75，或 ≤ 中位数×2）
  +10  title 长度 6～14（比 4～18 更「像一句人话」）
  +5   有 merchantBrandId 但 title 已用户改写（生活感）
  + stableHash(item.id + periodKey) % 5   // 同分打破平局，避免总选最大笔

--------------------------------------------------------------------------------
3.3 降级档（可选 · 仅当 title 候选 **0 条** 时）
--------------------------------------------------------------------------------

若 title 池为空，且 period 内 items.length ≥ 2：
  · 在 **有非默认 emotionTag** 的记录中选 1 条（同 §3.2 软排序，但 snippet = emotionTag）
  · kind = "emotion"
  · **MVP 可开关**：默认 **开启**（提高「有回指」概率，仍不编散文）

若仍无 → return null

--------------------------------------------------------------------------------
3.4 频率 cap
--------------------------------------------------------------------------------

  · 同一 periodKey **全局只选 1 条** Anchor（切片 / 周记 / 月记共用）
  · items.length < 2 → 不出锚点（防硬煽）

================================================================================
四、锚点句 formatEchoAnchorSentence(anchor) → String
================================================================================

**title 锚点**（kind=title，hash 二选一）：
  A. 「有一笔你写下「{snippet}」，像是那天给自己留的一点照顾。」
  B. 「{snippet}」—— 有一笔是这样留在账本里的。」

**emotion 降级锚点**（kind=emotion，仅 title 池空时用，1 条）：
  C. 「有一次你标记过「{snippet}」，像一段很小的生活注脚。」

禁止：
  · 「你应该/建议/占比/预算/心理分析」
  · snippet 为空仍输出
  · 同 period 同屏重复

snippet：title 原文（已 4～18 字，不再截）；emotion 用 tag 原文（通常 ≤8 字）

================================================================================
五、落点（综合 · 有优先级）
================================================================================

**同 period 锚点句在用户可见 UI 只出现 1 次。**

优先级（实现时固定一种，写入代码注释）：

  **1. 周/月切片 · highlight 幕**（主落点）
      iOS PlaybackService highlight 章
      Web buildTraceSliceChapters type=highlight
      有 anchor → narration = formatEchoAnchorSentence
      无 anchor → 保持现有结构叙述（title+金额 或 category 幕不变）

  **2. 复盘 · 周记一段**（备落点）
      formatWeeklyJournalText 段落 **末尾** 追加锚点句（句号连接）
      **仅当本 period 切片未展示锚点时** 插入

  **3. 月记**（MVP 可选）
      formatMonthlyJournalText 同理，periodKey=month，与月切片共享 cap

**不计入 cap 的低成本加强（建议顺手做）：**
  · 痕迹 slip / 票根：若 emotionTag 非默认，meta 行展示 tag（Web trace-slip-mood；iOS 票根）
  · 不算「锚点句」，不占用每周 1 次 — 只是记→望的 **弱闭环**

================================================================================
六、与「空泛 / 工具」的平衡
================================================================================

  结构层（笔数、分类、金额）= 骨架，**始终保留**
  锚点句 = 生活痕迹，**有则加半句，无则不加**
  细查 Sheet / 编辑 = 用户「要较真」时的可靠第二层（本任务不碰）

好 vs 坏：
  ✅ 「有一笔你写下「加班后吃点热乎的」，像是那天给自己留的一点照顾。」
  ✅ 「片刻停靠」—— 像一段很小的生活注脚。（emotion 降级）
  ❌ 「这周的你，在温柔与忙碌之间寻找平衡。」（空泛）
  ❌ 「餐饮占比 42%，建议关注。」（工具）

================================================================================
七、验收
================================================================================

造数：
  1. 3 笔含「加班后吃点热乎的」→ 切片 **或** 周记 **出现 1 次** 锚点
  2. 全默认标题/脏串 → 无锚点，叙述与改前一致
  3. 无合格 title 但有非默认 emotionTag → 可选出现 C 模板（若开启降级）
  4. 同周：切片已展示 → 周记 **不重复**
  5. slip 上可见 emotionTag（若做了 §五弱闭环）

回归：
  [ ] 无锚点周期行为零回归
  [ ] Web / iOS 选材规则一致
